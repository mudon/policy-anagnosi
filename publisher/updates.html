Updates & version policy

Control optional and required app updates with GitHub Pages and Google Play.

Publisher: mudonEffective / updated: 18 October 2026

On this page

The app now includes update checking. Deploy update-policy.json together with the public HTML. It keeps minimum code 4 and latest code 6, with no update prompt for the included build 6. Nothing has been deployed by this kit.

1. First deployment

Publish the contents of public/ in a public GitHub repository named anagnosi. In Settings → Pages choose Deploy from a branch, main, /(root). With the GitHub username mudon, the app's default policy address is https://mudon.github.io/anagnosi/update-policy.json. If you use a different repository or host, configure the app before building:

flutter build appbundle --release --dart-define=ANAGNOSI_UPDATE_POLICY_URL=https://YOUR-HOST/update-policy.json

Open the deployed address and confirm it returns JSON directly, without login, redirects or an HTML error. Keep packageId equal to the app's actual Android application ID. The default is com.anagnosi.reader. GitHub Pages deployment/CDN changes can take time.

This is a configuration file, so keep it publicly readable and include no secrets, identifiers or reading data. Host only your own intended update policy there. Do not upload the publisher folder or the app source ZIP as a replacement for the public files.

2. Optional versus required updates

The included app is 0.4.2+6. The integer after + is the Android version code. Increment this for every Play release. For a future 0.5.0+7 release:

Behaviour for build 6 usersminimumSupportedVersionCodelatestVersionCode
Build 7 is optional67
Build 7 is required77

Set latestVersionName to 0.5.0 and give a short reason in message. Release build 7 through Google Play and verify it is downloadable before changing the live policy. A new app build is not needed merely to edit the hosted policy.

{
  "schemaVersion": 1,
  "packageId": "com.anagnosi.reader",
  "enabled": true,
  "minimumSupportedVersionCode": 7,
  "latestVersionCode": 7,
  "latestVersionName": "0.5.0",
  "message": "Please update Anagnosi to continue reading."
}

Do not publish this build-7 example until build 7 is ready. The deployable public/update-policy.json keeps build 4 supported and makes build 6 optional. Required updates are intended for changes important to core functionality; ordinary improvements can stay optional.

3. What users see

The app checks on launch and when it returns to the foreground. Normal policy checks on resume are throttled to 15 seconds; there is no background polling after the app is closed. The native activity also checks Play for interrupted immediate updates when it resumes. A required screen covers the library, reader and any open dialog in the current evergreen theme. Reading state remains mounted, stored changes are flushed, and active speech stops. Users get Update now, Check again, Open Google Play and Close app.

Update now requests Google's immediate in-app flow, with the official Play listing as a fallback. Google Play handles installation after user consent. Cancelling or failing an update does not grant access to an unsupported build. Optional updates have Later and do not block reading. Updating normally preserves local app data; uninstalling or clearing app storage removes that data.

Version policy support begins in build 4. Earlier installed builds without the update-checking logic cannot be made to enforce it merely by uploading this JSON.

4. Offline use, eligibility and recovery

  • A new mandatory requirement is applied only after Google Play confirms an update meeting the minimum is available to that user/device. A staged rollout, withdrawn update or incompatible device must not be locked merely because the public JSON names a higher version.
  • First offline launch or a missing/invalid policy allows local reading. A device that stays offline before learning of an update cannot discover a new requirement.
  • After an eligible required update has been confirmed, its requirement is cached. It can stay blocking through cancellation, network loss and relaunch. A newly raised floor needs fresh eligibility confirmation.
  • A fresh successful Play result confirming no eligible required target releases the previous cache. Installing a supported version also releases the gate.
  • To recover from a release problem, set enabled to false in an otherwise valid policy, or lower the minimum. Devices need a connection to fetch that change. Disabling enforcement hides prompts but does not stop checks.
  • Deleting or breaking the policy is not a reliable recovery switch: a verified cached requirement may remain. Use valid JSON and confirm the deployed response.

This is local app enforcement. It cannot guarantee that modified binaries, deliberately deleted app state, service errors or devices that never connect will obey a new remote requirement. Do not tell users to clear storage or uninstall to bypass a gate; that risks their reading data.

5. Test the actual Google Play release

Use matching package/signing identities and an account that owns the app through Google Play. Install an older build containing the feature, then make a higher build available to that account through the correct testing track. Google also documents an internal-app-sharing test flow. A standalone debug APK is not proof that Play updates work.

  • Check supported/current, optional and required versions.
  • Cancel, fail and retry; background/kill the process during download; return from the store.
  • Compare first offline use with a previously verified cached requirement.
  • Exercise staged/withdrawn releases, invalid JSON, disabled enforcement and a lowered minimum.
  • Verify small screens, large text, accessibility, and books/notes/progress after installing.

Source verification passed 36 policy checks, 28 controller/channel checks and 6 separately labelled native source invariants. The controller checks use mocked platform/channel types. Flutter widget tests are included in the app source, but no Flutter widget run, Android compilation, real Play update or signed AAB is represented as completed in this environment.

6. Update data and official references

The policy host receives routine connection details such as IP address, request time/path and network headers. Anagnosi adds no book content, notes, version identifier or user identifier to this JSON request. Cached policy/eligibility information stays in private app preferences. Google Play separately processes the technical information needed to check and install updates. The public Privacy Policy and publisher Data safety worksheet have been updated accordingly.
